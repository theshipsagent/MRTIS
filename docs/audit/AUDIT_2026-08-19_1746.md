## 3. Verdict B — wrong, with evidence

### W1 — 54 legs are labelled "No Cargo" and bill anyway — **MEDIUM, $413,000**

**The claim.** `sql/schema_port_call.sql` and `docs/PORT_CALL_QUALITY.md` both
state: *"Real activity (Load/Discharge) always wins the leg's reported activity
over No Cargo; **only a leg with nothing but layberth stops reports No Cargo
itself**."*

**The first half is true. The second half is false.**

`build_port_calls.py:596-601`:

```python
real_acts = [st for st in lg if st["activity"] and st["activity"] != "No Cargo"]
act_src   = real_acts[0] if real_acts else next((st for st in lg if st["activity"]), None)
```

`real_acts` requires a **truthy** activity. An unresolved stop has
`activity = None`, which is falsy — so it cannot enter `real_acts`, and the
fallback picks the `No Cargo` stop. Meanwhile the fee test on the next line uses
a different predicate entirely:

```python
real_berth = any(st["activity"] != "No Cargo" for st in lg)   # None != "No Cargo" -> True
```

`None` *does* satisfy `real_berth`. So a leg holding one layberth stop and one
unresolved non-layberth stop is **labelled `No Cargo` and billed in full**.

**Measured on the rebuilt data:**

| | Legs | Fee |
|---|---|---|
| Legs with `activity = 'No Cargo'` | 196 | $413,000 |
| …of which contain a genuine non-layberth berth stop | **54** | **$413,000** |
| …of which are pure layberth (correctly $0) | 142 | $0 |

**Every dollar billed under a `No Cargo` label — all $413,000 — sits on a leg
the documentation says cannot exist.**

The berths involved are real working berths: Chalmette Slip (7 legs), IMC
Faustina (4), 7th Street (4), Arabi Terminal (3), IMTT St Rose 14, Blackwater
Harvey, Phillips 66 Alliance, Globalplex.

**Why it matters beyond the label.** Any downstream filter written against the
documented behaviour — `WHERE activity <> 'No Cargo'` to isolate revenue work,
or `WHERE activity = 'No Cargo'` to find unbilled lay-ups — returns the wrong
answer on all 54. The label and the money disagree, and the schema comment
promises they cannot.

**Two related inconsistencies fall out of the same code path:**

- **7 `No Cargo` legs assert a `cargo_group`.** `cargo_group` is read from
  `lg[0]["zinfo"]` — the leg's *first* stop — while `activity` is read from a
  possibly *different* stop. Result: legs labelled `No Cargo` carrying
  `cargo_group = 'Liquid Bulk'` (IMC Faustina ×3, IMTT St Rose 14, LBC Sunshine,
  PCS Nitrogen) and one carrying `'Passengers'` (Julia St, a cruise berth).
  The `no cargo is asserted without a source` guardrail passes, because
  `cargo_source` is populated — it checks provenance, not coherence.
- **`first_berth_zone`, `facility_type` and `first_berth_facility` likewise
  describe `lg[0]`**, not the stop that generated the fee. On 20 of the 54 the
  leg reports the layberth (Buck Kreihs, Perry Street, Poland St, Violet Dock 2,
  Alabo St) as its berth while billing for work done elsewhere.

**Not fixed. Recommended framing:** either an unresolved stop should outrank
`No Cargo` for the label (making these legs `NULL`/unresolved, which is honest),
or the leg needs a separate `billable_activity` column. That is a business
decision — routed to `OPEN_QUESTIONS.md`.

### W2 — "unchanged from before this fix" is not a like-for-like comparison — **MEDIUM, $3,258,500**

**The claim** (`docs/PORT_CALL_QUALITY.md:86`): the 54 legs *"bill exactly as
[they] did before this ruling; only the layberth stop itself is fee-exempt."*

**This cannot be true as stated, because §8 changed which stops are in which
leg.** The pre-§8 `build_port_calls.py` was checked out and the layer rebuilt.
The leg population is not the same population:

| | Pre-§8 | Post-§8 |
|---|---|---|
| Legs (total) | 41,985 | 41,804 |
| Split calls | 1,787 | 1,632 |
| Legs touching a layberth | 442 | 421 |
| — pure layberth | 300 (all charged, $3,017,000) | 142 (**$0**) |
| — layberth + other berth | 142 ($980,000) | **279 ($2,404,500)** |
| Legs labelled `No Cargo` | 402 | 196 |
| `No Cargo` legs billing | **$3,717,000** | **$413,000** |

The "54 legs billing $413,000" cohort **did not exist before the fix**. There
were 142 mixed legs billing $980,000; §8 merged 158 previously-separate
layberth legs into their neighbours, producing 279 mixed legs. Comparing
$413,000 to itself across that boundary is comparing two different sets of rows.

**The figure that is actually true, and is stated nowhere:**

> **§8 reduced billing by $3,258,500 — from $302,127,000 to $298,868,500 —
> across 313 port calls.**

Per-call movement: 284 calls −$10,500, 19 calls −$3,500, 10 calls −$21,000.
That is **1.08% of the pre-fix ruling basis**, and it is the number a reviewer
of the §8 ruling needs in order to sanity-check it.

To be clear about what *is* sound: the reduction is correct and intended — 142
pure-layberth legs correctly stopped billing, and 181 legs correctly ceased to
exist as separate legs. The defect is in the reporting, not the arithmetic.

`port_call.agency_fee_departures_total` exists, per the schema comment, so the

### W4 — the `ship_type_group` backfill does not implement its stated condition — **LOW (latent), $0 today**

**The claim:** *"`ship_type_group` is backfilled from `ship_type` wherever the
register has no size vocabulary for that family."*

**The code has no such condition.** `build_db.py:266` is an unconditional
row-level fill:

```python
reg["ship_type_group"] = reg["ship_type_group"].fillna(reg["ship_type"])
```

Nothing inspects whether the family has a size vocabulary. The stated guard is
a description of the data at the time of writing, not of the code.

**Against the live register it is dead code.** The refreshed
`ships_register_fleet.csv` has **0 blank `ship_type_group`** values, so the
`fillna` matches nothing. Verified.

**Against the register it was written for, it happened to be right.** The
pre-§9 register had 1,349 blanks, and **all 1,349** belonged to families with no
size vocabulary anywhere in the file — Aggregates Carrier (764), Cement Carrier
(445), Bulk Carrier Self-discharging Laker (57), Limestone Carrier (46), and
five smaller families. **0 illegitimate fires.** The claim's *effect* was
correct; the claim's *mechanism* was not.

**Why this is worth recording rather than dismissing.** The backfill writes a
raw family name into a column that `agency_fee_for()` pattern-matches:

```python
return (AGENCY_FEE_BULK if ship_type_group.startswith("Bulk Carrier") else AGENCY_FEE_OTHER)
```

`'Bulk Carrier, Self-discharging, Laker'` **starts with `"Bulk Carrier"`**. Under
the old register, the backfill therefore promoted 57 Laker rows to the $10,500
tier by string prefix — correct by luck, not by design. A future register
revision that reintroduces blanks in a family whose name happens to begin
`"Bulk Carrier"` will silently move vessels to the higher tier at **$7,000 per
leg**, with no guardrail to catch it.

**Live exposure today: $0.** The 20 vessels whose `ship_type_group` equals
their bare `ship_type` and whose `Type` is blank are all tugs, OSVs, research
and pilot vessels (`Yacht`, `Tug`, `Platform Supply Ship`, `Anchor Handling
Vessel`, …). None matches `Bulk Carrier*`; all price at $3,500, which is what
they would price at with no register row at all.

## 5. Guardrail coverage — what the checks do not check

The eighteen hard guardrails are correct and were independently confirmed. They
are also **structural only**: every one asserts a shape (uniqueness, referential
integrity, set equality, ordering, sum-of-parts). Not one asserts a *value* is
right. The gaps below are all currently clean — which is exactly why they are
worth naming, since nothing would catch them going wrong.

| Gap | Today | Would catch |

## 6. What is genuinely well built

Worth stating plainly, because the findings above are all narrow:

- **Evidence is ranked, not averaged.** `resolve_activity()` names its method on

- **The pre-ruling basis really is preserved.** Both rulings were tested by
  rebuild against their own predecessors, and neither moved it by a dollar.
